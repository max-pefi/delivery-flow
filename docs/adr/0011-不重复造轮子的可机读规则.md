# ADR 0011: 不重复造轮子的可机读规则（L1/L2/L3 三层结构）

- **日期**: 2026-08-26
- **状态**: 已采纳
- **承接**: ADR 0001（分层设计总纲）、ADR 0004（阈值不预设数字）、ADR 0010（项目计划与治理层）

## 背景

ADR 0001 / 0010 仅以 prose 形式写下「不重复造轮子」「不复制 BMAD/Superpowers/lark-* 实现」。后果：

1. **不可机读**：AI agent 看不到这条规则，跑插件时仍会跑去用 lark-task / superpowers 等外部 skill
2. **新增 skill 无强制检查**：仓库无「先查重再新增」的流程
3. **CI 无拦截**：仓库无 `.github/workflows/`，更无 SKILL.md 描述字段的校验

## 决策

把 ADR 0001 的 prose 规则升级为三层结构：

### L1 元数据层（`plugin.json`）

把 `"dependencies": []` 改为 4 项数组，标注 tier：

```json
"dependencies": [
  {"name": "bmad-method", "tier": "required", ...},
  {"name": "superpowers", "tier": "recommended", ...},
  {"name": "lark-skills", "tier": "optional", ...},
  {"name": "project-management", "tier": "optional", ...}
]
```

**为什么用数组而非 dict**：Claude plugin schema 历史上是数组，保守兼容。三档语义（required/recommended/optional）在每个对象的 `tier` 字段里表达。

### L2 边界登记层（`CAPABILITY_BOUNDARIES.md`）

每个自建 skill 一段三行固定格式：

```
### delivery-{name}
> 边界：{自建能力本质 + 与外部 skill 的分工}
> 标签：{UNIQUE | BOUNDARY_DECLARED | OVERLAP_REMOVED}
> 别名：{comma-separated}
```

**为什么不用 YAML frontmatter**：会与 SKILL.md 的 `---` 冲突。markdown 表格需要转义 `|` 和对齐。三行固定格式用正则一句一解析，段落增删不影响脚本。

### L3 校验层（`check_capability_overlap.py` + GitHub Actions）

算法：

1. 剥触发句 `当用户说.*?时使用[。\.]?`
2. 中文按字 bigram，英文按词（≥2 字符）
3. **Overlap 系数** = `|A∩B| / min(|A|, |B|)`（**不是** Jaccard；Jaccard 在短描述下被稀释失效）
4. 阈值：≥0.8 FAIL / ≥0.6 WARN / <0.6 PASS
5. WARN 阶段：若目标 skill 在 `CAPABILITY_BOUNDARIES.md` 声明 `BOUNDARY_DECLARED` 或 `OVERLAP_REMOVED`，降级为 PASS

CI trigger：PR 修改 `skills/**` / `CAPABILITY_BOUNDARIES.md` / `plugin.json` / `external_skills.json` / 校验脚本自身 / workflow 自身，触发 `--diff origin/master --include-untracked` 与全量回归。

## 与 ADR 0004 的边界

ADR 0004「阈值不预设数字」适用于**业务评测**（交付阈值/性能指标）。本 ADR 0011 的「0.8 / 0.6 阈值」是**校验算法参数**（CI 工具的判定阈值），不是业务阈值——两者不冲突。本 ADR 在 ADR 0001 的「观测指标」章节明确写「以下为观测值而非目标阈值」，遵守 ADR 0004 的精神。

## 与 ADR 0010 的关系

ADR 0010 说「不复制 BMAD/Superpowers/lark-* 实现」。本 ADR 0011 是它的工程化落地：把 prose 规则变成可机读 + 可校验的 CI 门槛。

## 后果

- **正面**：新增 skill 必须先在 CAPABILITY_BOUNDARIES.md 登记 + 通过校验脚本，规则可强制
- **正面**：AI agent 跑插件时 plugin.json 的 dependencies 字段是元数据可见的（不再是空数组否认依赖）
- **正面**：中文能力描述的重叠有客观可计算的判定标准，不再靠人肉审
- **代价**：每个新 skill 增加一次脚本运行 + CI 检查（秒级，可忽略）
- **代价**：CAPABILITY_BOUNDARIES.md 需人工维护三行（21 个 skill 总共 ~80 行，可接受）

## 出处

- `.claude-plugin/plugin.json`（L1）
- `.claude-plugin/CAPABILITY_BOUNDARIES.md`（L2）
- `.claude-plugin/external_skills.json`（外部 skill 清单，配合 L2）
- `scripts/check_capability_overlap.py`（L3 算法实现）
- `tests/unit/test_check_capability_overlap.py`（L3 单元测试，16 用例）
- `.github/workflows/skill-overlap-check.yml`（L3 CI 触发）
- `docs/adr/0001-分层设计-只补BMAD缺的四关卡.md`「观测指标」章节

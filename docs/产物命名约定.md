# 产物命名约定

本文档集中定义 delivery-flow 流水线中所有产物的标准文件名和目录结构。
所有 Skill、自动化检查器（delivery-check/trace）和 `core.py` 的 glob 模式均以此为准。

## 机器文件 vs 人读产物

**机器文件**（`core.py` 自动读取的契约/状态文件）放**项目根**固定位置；**人读产物**（方案、报价单、记录等）按阶段分文件夹。

### 机器文件清单（项目根固定）

| 机器文件 | 推荐位置 | 兼容旧位置 | 说明 |
|---|---|---|---|
| `SPEC.md` | `<项目根>/SPEC.md` | `<项目根>/04-需求分析/SPEC.md`、`<项目根>/_meta/SPEC.md` | 机读契约 |
| `project-progress.yaml` | `<项目根>/project-progress.yaml` | `<项目根>/_meta/project-progress.yaml` | 流水线宏观阶段 |
| `sprint-status.yaml` | `<项目根>/sprint-status.yaml` | `<项目根>/07-开发/sprint-status.yaml`、`<项目根>/_meta/sprint-status.yaml` | 飞书状态只读镜像 |
| `_映射表.json` | `<项目根>/_映射表.json` | `<项目根>/07-开发/_映射表.json`、`<项目根>/_meta/_映射表.json` | 飞书任务映射 |
| `_商机映射表.json` | `<项目根>/_商机映射表.json` | `<项目根>/_meta/_商机映射表.json` | 商机↔飞书 record_id |
| `desired-tasks.json` | `<项目根>/desired-tasks.json` | `<项目根>/07-开发/desired-tasks.json`、`<项目根>/_meta/desired-tasks.json` | PM 意图清单（dry-run 的写端） |

> `core.py` 的 `resolve_artifact()` 按 **根 → 阶段目录 → `_meta`** 顺序兼容读取。新项目统一写根；不自动迁移用户已有文件。

### 人读产物（按阶段文件夹整理）

- 阶段文件夹：编号 + 名称，emoji 标记状态（见下文）
- 文件带 `[序号]` 编号
- 每个文件按类型命名，避免模糊文件名

## 目录结构规范

每个项目按**阶段**分文件夹组织人读产物；机器文件放项目根。


### 阶段文件夹清单

| 序号 | 文件夹名 | 包含阶段 | 核心产物 |
|------|---------|---------|---------|
| 00 | `00-项目资料/` | 全程 | 客户提供资料、会议记录 |
| 01 | `01-商机确认/` | 商机确认 | 商机档案、市场调研 |
| 02 | `02-方案报价/` | 方案/报价 | 技术方案、报价单、售前原型 |
| 03 | `03-签约立项/` | 签约关卡 | 合同签约确认记录、立项包 |
| 04 | `04-需求分析/` | 需求接入 | project-context、SPEC、PRD |
| 05 | `05-设计/` | UX + 原型 | UX 文档、正式原型 |
| 06 | `06-架构/` | 架构设计 | 业务/产品/技术/数据四层架构 + readiness-report |
| 07 | `07-开发/` | 拆任务 + 研发 | stories、sprint-status、映射表 |
| 08 | `08-测试验收/` | 评测 + 测试 + 验收 | 评测报告、测试报告、验收报告 |

### 阶段状态标记（文件夹 emoji 前缀）

| 标记 | 含义 | 说明 |
|------|------|------|
| `▶ ` | 当前进行中 | 同一时刻只有一个文件夹带此标记 |
| `✅ ` | 已完成 | 该阶段所有产物已通过关卡 |
| `○ ` | 未开始 | 前置阶段完成后方可进入 |

> **更新时机**：每完成一个阶段并通过关卡后，将 `▶ ` 移到下一个文件夹，上一个自动改为 `✅ `。

### 文件顺序编号规则

- 同一文件夹内的文件用 `[01]`、`[02]`、`[03]`... 编号
- 编号表示文件在阶段内的**生成顺序**，也方便引用
- 编号不跨文件夹连续，每个文件夹从 `[01]` 重新开始

## 命名规则总览

| 规则 | 说明 | 示例 |
|------|------|------|
| **项目根文件夹** | `<项目名>-<年份>` | `学工系统-2026` |
| **阶段文件夹** | `{序号}-{阶段名}` | `01-商机确认`、`06-架构` |
| **产物文件** | `[序号] 文件名.扩展名` | `[01] 商机档案.md`、`[02] SPEC.md` |
| **日期后缀** | `{类型}-{YYYY-MM-DD}.md`，支持同类型多份 | `客户确认记录-2026-07-30.md` |
| **机器文件** | 项目根固定名（SPEC.md / project-progress.yaml / sprint-status.yaml / _映射表.json 等） | 兼容旧位置：阶段目录或 `_meta/` |
| **会议记录** | `{日期}-{主题}-{参会人}-逐字稿.md`（原始）/ `-纪要.md`（整理后） | `2026-08-03-方案评审会-张总李工-逐字稿.md` |
| **模板文件** | 中文"模板"后缀或英文 `template`，会被 `find_first` 自动排除 | `project-context模板.md` |

## 产物清单

### 根目录产物（机器文件，项目根 `/`）

| 产物 | 标准文件名 | 说明 |
|------|-----------|------|
| 项目上下文 | `project-context.md` | 固定名，含红线/阈值/验收线 |
| 需求规格（机读契约） | `SPEC.md` | 固定名，Why/Capabilities/Constraints/Non-goals/Success signal，头部可含 `> 商机编号: OPP-YYYY-NNN` 引用行 |
| 阶段进度 | `project-progress.yaml` | 固定名，流水线宏观阶段追踪 |
| 状态镜像 | `sprint-status.yaml` | 固定名，飞书单向拉取的只读镜像 |
| 映射表 | `_映射表.json` | 固定名，下划线前缀 |
| 商机映射表 | `_商机映射表.json` | 固定名，商机↔飞书 record_id |

### 目录产物

| 目录 | 标准路径 | 内部文件命名 | 说明 |
|------|---------|-------------|------|
| Story 文档 | `stories/` | `{story-id}.md` | story-id 由 BMAD 生成 |
| HTML 原型（售前） | `02-方案报价/演示原型/` | `index.html`（及其他资源） | 售前演示用，可选 |
| HTML 原型（正式） | `05-设计/演示原型/` | `index.html`（及其他资源） | 交付阶段正式原型 |
| 客户提供资料 | `00-项目资料/客户提供/` | 原样存放，不改文件名 | 客户原始文件 |
| 会议记录 | `00-项目资料/会议记录/` | `{日期}-{主题}-{参会人}-逐字稿.md` / `-纪要.md` | 逐字稿为原始证据链；纪要为结构化提炼 |

### 系统/配置文件

| 文件 | 标准路径 | 说明 |
|------|---------|------|
| 项目宪法 | `项目宪法.md` | 面向人读的治理文档（可选） |
| 投影配置 | `project-context.md` | AI Agent 注入的机读版 |
| 阶段进度 | `project-progress.yaml` | 项目根固定；兼容 `_meta/project-progress.yaml` |
| 状态镜像 | `sprint-status.yaml` | 项目根固定；兼容 `07-开发/sprint-status.yaml`、`_meta/sprint-status.yaml` |
| 映射表 | `_映射表.json` | 项目根固定；兼容 `07-开发/_映射表.json`、`_meta/_映射表.json` |
| 商机映射表 | `_商机映射表.json` | 项目根固定；兼容 `_meta/_商机映射表.json` |

> 旧布局 `_meta/` 系统文件目录在新项目中**不推荐**使用，保留仅为兼容存量项目。`core.py` 会自动从根 → 阶段目录 → `_meta` 顺序解析。

## 自动排除规则

`core.py` 的 `find_first()` 函数在匹配产物时自动排除：

- 文件名含 `template`（英文，不区分大小写）
- 文件名含 `模板`（中文）
- 文件名含 `示范`（中文）

路径排除（`core.py` 的 `_is_excluded()`）：

- 路径含 `/skills/`（skill 资产）
- 路径含 `/_bmad/`（BMAD 基座）
- 路径含 `/.agents/`（agents 配置）
- 路径含 `/.claude/`（Claude Code 配置）
- 路径含 `/.cursor/`（Cursor 配置）
- 路径含 `/.windsurf/`（Windsurf 配置）

## glob 模式速查

以下是 `core.py` 中用于识别各产物的 glob 模式（按优先级排序）：

| 产物 | glob 模式 |
|------|----------|
| 商机档案 | `*商机档案*.md` → `**/*商机档案*.md` |
| 报价单 | `*报价单*.md` → `**/*报价单*.md` |
| 立项包/签约记录 | `立项包.md` → `**/立项包.md` → `*合同签约确认*.md` → `**/*合同签约确认*.md` |
| 商机映射表 | `_商机映射表.json`（项目根）→ `**/_商机映射表.json` |
| 商机编号（Trace 根） | SPEC.md 头部正则 `商机编号[:：]\s*(OPP-\d{4}-\d+)`，回退 `project-progress.yaml` 顶层 `trace_id` |
| SPEC.md | `resolve_artifact`：根 → 04-需求分析 / 06-架构 → `_meta` |
| 业务架构 | `*业务架构*.md` → `**/*业务架构*.md` |
| 产品架构 | `*产品架构*.md` → `**/*产品架构*.md` |
| 技术架构 | `*技术架构*.md` → `**/*技术架构*.md` |
| 数据架构 | `*数据架构*.md` → `**/*数据架构*.md` |
| 客户确认记录 | `*客户确认*.md` → `**/*客户确认*.md` |
| 技术就绪报告 | `*readiness*.md` → `**/*readiness*.md` → `**/*技术就绪*.md` |
| 验收报告 | `*验收报告*.md` → `**/*验收报告*.md` |
| 评测报告 | `*评测报告*.md` → `**/*评测报告*.md` |
| Story 文档 | `stories/**/*.md` → `**/*story*.md` → `**/*stories*.md` |
| 映射表 | `resolve_artifact`：根 → 07-开发 → `_meta` |
| 状态镜像 | `resolve_artifact`：根 → 07-开发 → `_meta` |
| 阶段进度 | `resolve_artifact`：根 → `_meta` |

## 注意事项

- **不要用模糊文件名**：如 `需求.md`、`文档.md`——这些会匹配多个产物，导致误判。
- **日期格式统一用 ISO**：`YYYY-MM-DD`，不用 `YYYYMMDD` 或 `YYYY.MM.DD`。
- **PRD/UX 用固定名**：不用 `PRD-v2.md` 或 `UX-终稿.md`，版本通过 git 追踪。
- **映射表和状态文件用下划线前缀**：表明是系统内部文件，不是交付产物。
- **客户提供资料原样存放**：不改文件名、不转格式，保持原始证据链。

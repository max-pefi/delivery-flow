# 跨工具安装指南

> 本指南面向**非 Claude Code** 用户（Codex / Cursor / Windsurf 等）。Claude Code 用户直接在对话中说"装 delivery-flow"即可，无需阅读本文件。

---

## 快速开始（一行命令）

如果你已经 clone 了 delivery-flow 到 `D:/tools/delivery-flow`，**最快的方式**是跑仓库根的 `setup.sh`（Git Bash）或 `setup.ps1`（PowerShell），自动生成所有配置。

### Git Bash（推荐）

```bash
cd D:/code/你的新项目
bash <(curl -fsSL https://raw.githubusercontent.com/fredsimas782-jpg/delivery-flow/main/setup.sh) \
  --plugin-path D:/tools/delivery-flow
```

需要同时装 BMAD：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/fredsimas782-jpg/delivery-flow/main/setup.sh) \
  --plugin-path D:/tools/delivery-flow \
  --bmad \
  --bmad-tools claude-code
```

**一步到位**（再 + 复制项目模板）：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/fredsimas782-jpg/delivery-flow/main/setup.sh) \
  --plugin-path D:/tools/delivery-flow \
  --bmad --init
```

### PowerShell

```powershell
cd D:\code\你的新项目
irm https://raw.githubusercontent.com/fredsimas782-jpg/delivery-flow/main/setup.ps1 | iex `
  -PluginPath D:\tools\delivery-flow
```

需要同时装 BMAD：

```powershell
irm https://raw.githubusercontent.com/fredsimas782-jpg/delivery-flow/main/setup.ps1 | iex `
  -PluginPath D:\tools\delivery-flow `
  -Bmad `
  -BmadTools claude-code
```

**一步到位**：

```powershell
irm https://raw.githubusercontent.com/fredsimas782-jpg/delivery-flow/main/setup.ps1 | iex `
  -PluginPath D:\tools\delivery-flow `
  -Bmad -Init
```

### `--init` 项目模板初始化

启用 `--init` 后脚本会从 `$PLUGIN_PATH/templates/` 复制两个核心文件到当前目录，并把 `{{项目名}}` / `{{负责人}}` / `{{日期}}` 占位符替换成实际值：

| 输出文件 | 来源模板 | 必填？ | 用途 |
|---|---|---|---|
| `project-context.md` | `templates/project-context模板.md` | ✅ AI 必读 | 项目宪法：技术栈/红线/风险防线/验收线；含「模型分层策略」节（5 列表：阶段 / 思考模型+工具 / 执行模型+工具 / 触发词 / **交接文件**） |
| `project-progress.yaml` | `templates/project-progress模板.yaml` | ✅ 状态机 | 流水线阶段追踪，AI 第一句"现在到哪了"读它 |

**Codex 用户的特殊说明**：看 `AGENTS.md` 第 7 节 B 栏（跨工具交接）+ `.codex-plugin/plugin.json` 里的 `model_strategy` 字段。Codex CLI 的 `/plan` 模式对应思考模型（SOL）、`/code` 模式对应执行模型（mini）。跨工具交接时方案落到 `<交接文件>` 默认 `<阶段目录>/[NN] <产物>.draft.md`。

| 脚本 | 参数 | 默认 | 说明 |
|---|---|---|---|
| sh | `--init` | 关闭 | 总开关 |
| sh | `--init-name <name>` | 当前目录名 | 替换 `{{项目名}}` |
| sh | `--init-user <name>` | `$USER` | 替换 `{{负责人}}` |
| sh | `--init-date <yyyy-mm-dd>` | 今天 | 替换 `{{日期}}` |
| sh | `--init-force` | 关闭 | 覆盖已存在文件（默认 skip） |
| sh | `--no-init-progress` | 关闭 | 只复制 context，不复制 progress |
| sh | `--no-init-context` | 关闭 | 只复制 progress，不复制 context |
| ps1 | `-Init` / `-InitName` / `-InitUser` / `-InitDate` / `-InitForce` / `-NoInitProgress` / `-NoInitContext` | 同上 | 参数名 PascalCase |

**典型用法**：

```bash
# 默认：项目名=目录名，负责人=$USER，日期=今天
bash setup.sh --plugin-path D:/tools/delivery-flow --init

# 自定义项目名 + 负责人
bash setup.sh --plugin-path D:/tools/delivery-flow --init \
  --init-name 智能客服v2 \
  --init-user "张三"
```

### 先 dry-run 看一眼（推荐）

```bash
# Git Bash
bash setup.sh --plugin-path D:/tools/delivery-flow --bmad --init --dry-run

# PowerShell
irm https://raw.githubusercontent.com/fredsimas782-jpg/delivery-flow/main/setup.ps1 | iex `
  -PluginPath D:\tools\delivery-flow -Bmad -Init -DryRun
```

脚本只打印「将要做什么」，不写文件、不建软链接、不调 `npx`。确认无误后去掉 `--dry-run` / `-DryRun` 真跑。CI 流水线里也推荐用 dry-run 模式做预演。

### 装完跑一遍 verify（推荐）

```bash
# Git Bash
bash <(curl -fsSL https://raw.githubusercontent.com/fredsimas782-jpg/delivery-flow/main/setup-verify.sh)

# PowerShell
irm https://raw.githubusercontent.com/fredsimas782-jpg/delivery-flow/main/setup-verify.ps1 | iex
```

**检查 7 项**：

| 项 | 严重级 | 含义 |
|---|---|---|
| Claude Code 软链接 | ERROR / INFO | 软链接不可达 = AI 找不到插件 |
| AGENTS.md 占位符 | WARN / OK | 仅查头部 10 行，避免误报模板里的「待填写」 |
| `.cursor/rules/delivery-flow.mdc` | INFO / OK | 仅 Cursor 用户 |
| `.windsurf/rules/delivery-flow.md` | INFO / OK | 仅 Windsurf 用户 |
| `_bmad/` 目录 | INFO | BMAD 安装痕迹 |
| `project-context.md` 占位符 | WARN / OK | AI 必读 |
| `project-progress.yaml` + current_stage | WARN / OK | 状态机 |

**退出码**：`0=全 OK` / `1=有 WARN` / `2=有 ERROR`。脚本同时支持 `--json` / `-Json` 输出供 AI 自动解析。

**AI 排错入口**：在 Claude Code 里说「帮我 verify 一下」或「setup 出问题了」，AI 跑 `setup-verify --json` 拿结构化结果自动给修复建议。

### BMAD 自动安装相关参数

| 脚本 | 参数 | 默认 | 说明 |
|---|---|---|---|
| sh | `--bmad` | 关闭 | 启用 BMAD 自动安装 |
| sh | `--bmad-tools <list>` | `claude-code` | 工具列表（多个用逗号，如 `claude-code,cursor`） |
| sh | `--bmad-modules <list>` | 空 | 模块列表（空=用 installer 默认） |
| sh | `--bmad-timeout <sec>` | `600` | 超时秒数 |
| ps1 | `-Bmad` | 关闭 | 启用 BMAD 自动安装 |
| ps1 | `-BmadTools <list>` | `claude-code` | 同上 |
| ps1 | `-BmadModules <list>` | 空 | 同上 |
| ps1 | `-BmadTimeout <sec>` | `600` | 超时秒数 |

**前置要求**：机器已装 Node.js 18+（含 `npx`）。脚本会自动检测；没有就报错并打印安装指引，**不会中断其他配置步骤**。

**BMAD 失败怎么办**：
- 脚本会打印失败原因和手动重跑命令
- AGENTS.md / 软链接 / Cursor / Windsurf 等其他配置已经完成，不影响使用
- 可以晚点再单独跑：`npx -y bmad-method install --directory . --tools claude-code --yes`

### 脚本做了什么

| 输出文件 | 用途 | 适用工具 |
|---|---|---|
| `AGENTS.md` | 项目 AI 工作指令（精简版） | Codex / 其他 |
| `.claude/plugins/delivery-flow` | 软链接到插件目录 | Claude Code |
| `.cursor/rules/delivery-flow.mdc` | Cursor 规则文件 | Cursor |
| `.windsurf/rules/delivery-flow.md` | Windsurf 规则文件 | Windsurf |

如果不需要某个工具的配置文件，用开关跳过：

```bash
bash setup.sh --plugin-path D:/tools/delivery-flow --no-cursor --no-windsurf
```

```powershell
.\setup.ps1 -PluginPath D:\tools\delivery-flow -NoCursor -NoWindsurf
```

**1. 在项目根创建 `AGENTS.md`**（如已存在则在末尾追加）：

### 其他工具

如果你使用的工具不在上述列表中：

1. 将 `<DF_PATH>/skills/` 路径告知你的 AI agent
2. 在项目根创建 `project-context.md`（从 `<DF_PATH>/templates/project-context模板.md` 复制）

## 本地软链接配置（Claude Code 用户必看）

> **为什么需要软链接**：Git 不会提交符号链接的内容，每个人的电脑路径都不一样。所以**每个新人 clone 项目后都要建一次软链接**，让 Claude Code 能找到插件。

### Claude Code 软链接

**前置**：插件已 clone 到 `D:/tools/delivery-flow`（或你自己的路径）。

#### 方式一：Git Bash（推荐）

```bash
# 进入你的项目根
cd D:/code/你的项目

# 建插件软链接
mkdir -p .claude/plugins
ln -s /d/tools/delivery-flow .claude/plugins/delivery-flow

# 验证
ls .claude/plugins/delivery-flow/skills/
# 应看到 delivery-presales/ delivery-deal-gate/ 等 21 个目录
```

#### 方式二：PowerShell（管理员）

```powershell
# 进入你的项目根
cd D:\code\你的项目

# 建插件软链接
New-Item -ItemType Directory -Path ".claude\plugins" -Force
New-Item -ItemType SymbolicLink -Path ".claude\plugins\delivery-flow" -Target "D:\tools\delivery-flow"

# 验证
Get-Item .claude\plugins\delivery-flow | Select-Object LinkType, Target
```

#### 方式三：Windows 命令行（管理员 cmd）

```cmd
cd /d D:\code\你的项目
mkdir .claude\plugins
mklink /D .claude\plugins\delivery-flow D:\tools\delivery-flow
```

### 验证软链接是否生效

在 Claude Code 中打开项目，说：

> "现在到哪了"

AI 应该自动调 `delivery progress` 并返回阶段信息。**如果 AI 说找不到插件路径**：

1. 检查软链接是否存在：`ls .claude/plugins/`（Git Bash）或 `dir .claude\plugins\`（cmd）
2. 检查目标路径是否存在：`ls D:/tools/delivery-flow/skills/`
3. 删除重建：`rm .claude/plugins/delivery-flow && ln -s /d/tools/delivery-flow .claude/plugins/delivery-flow`

### 跨电脑迁移

换电脑或重装系统后：

1. 重新 clone delivery-flow 到 `D:/tools/delivery-flow`（路径建议固定，方便所有项目共享）
2. 每个项目目录重建软链接
3. `AGENTS.md` 里检查插件路径是否一致

## 验证安装完成

无论使用哪种工具，确认以下文件存在：

| 文件 | 状态 |
|---|---|
| `project-context.md` | ✅ 已创建并填入项目信息 |
| `project-progress.yaml` | ✅ 已创建，current_stage: requirements |
| `_bmad/` | ✅ BMAD 已安装（或标记为手动处理） |
| 对应工具的配置文件 | ✅ 已包含 delivery-flow 引用 |

完成后，在你的 AI 工具中说"我该做什么"即可开始使用 delivery-flow。

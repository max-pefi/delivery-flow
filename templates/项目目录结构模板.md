# 项目目录结构模板

> 新项目启动时，复制此结构作为初始目录树。
> 将 `<项目名>-<年份>` 替换为实际项目名（如 `学工系统-2026`）。
>
> **核心原则**：机器文件（core.py 自动读取）放项目根；人读产物按阶段分文件夹。
> `core.py` 的 `resolve_artifact()` 会按 根 → 阶段目录 → `_meta` 兼容读取旧布局，但新项目统一写根。

## 目录树

```
<项目名>-<年份>/
│
├── SPEC.md                          ← 机器文件（机读契约）
├── project-progress.yaml            ← 机器文件（流水线阶段）
├── sprint-status.yaml               ← 机器文件（飞书状态只读镜像）
├── _映射表.json                     ← 机器文件（飞书任务映射）
│
├── 00-项目资料/
│   ├── 客户提供/
│   │   └── .gitkeep
│   └── 会议记录/
│       └── .gitkeep
│
├── ○ 01-商机确认/
│   ├── [01] 商机档案-{YYYY-MM-DD}.md     ← 售前：商机确认时生成，含 Trace 根
│   ├── [02] 市场调研报告.md               ← 可选：委托 BMAD 做 market-research
│   └── [03] 竞品分析.md                   ← 可选
│
├── ○ 02-方案报价/
│   ├── [01] 技术方案.md                   ← 售前：方案设计
│   ├── [02] 报价单-{YYYY-MM-DD}.md        ← 售前：报价，日期后缀支持多轮
│   └── [03] 演示原型/                     ← 可选：售前演示用 HTML 原型
│       └── index.html
│
├── ○ 03-签约立项/
│   ├── [01] 合同签约确认记录-{YYYY-MM-DD}.md  ← deal-gate 产出，冻结商务基线
│   └── [02] 立项包.md                     ← deal-gate 产出，商务→交付移交
│
├── ○ 04-需求分析/
│   ├── [01] project-context.md            ← 项目上下文（红线/阈值/验收线）
│   ├── [02] PRD.md                        ← 产品需求文档
│   ├── [03] 客户确认记录-{YYYY-MM-DD}.md  ← client-gate 产出（也可放根）
│   └── （SPEC.md 兼容位置，新项目放根）
│
├── ○ 05-设计/
│   ├── [01] UX.md                         ← bmad-ux 产出（DESIGN/EXPERIENCE）
│   └── [02] 演示原型/                     ← 正式 HTML 原型（基于 UX 重做）
│       └── index.html
│
├── ○ 06-架构/
│   ├── [01] 业务架构.md                   ← 业务全景 + 系统定位 + 与现有系统关系
│   ├── [02] 产品架构.md                   ← 模块划分 + 模块关系 + 功能地图
│   ├── [03] 技术架构.md                   ← 技术选型 + 部署结构 + 架构不变量
│   ├── [04] 数据架构.md                   ← 核心实体 + 数据流 + 数据安全
│   └── [05] readiness-report.md           ← 四文档对齐检查（关卡证据）
│
├── ○ 07-开发/
│   ├── stories/                           ← story 文档目录
│   │   └── .gitkeep
│   └── （sprint-status.yaml / _映射表.json 兼容位置，新项目放根）
│
└── ○ 08-测试验收/
    ├── [01] 评测报告-{YYYY-MM-DD}.md      ← AI 评测（eval-loop）
    ├── [02] 测试报告.md                   ← QA 测试
    └── [03] 验收报告-{YYYY-MM-DD}.md      ← 客户验收（acceptance-gate）

# 旧布局 `_meta/` 仅作兼容保留，新项目不要使用
# ├── _meta/
# │   ├── project-progress.yaml            ← 旧布局兼容位置
# │   ├── _商机映射表.json                 ← 旧布局兼容位置
# │   └── _飞书映射表.json                 ← 旧布局兼容位置
```

## 机器文件 vs 人读产物

| 类型 | 位置 | 命名规则 | 例子 |
|------|------|---------|------|
| **机器文件** | 项目根固定 | 标准文件名 | `SPEC.md` / `project-progress.yaml` / `sprint-status.yaml` / `_映射表.json` |
| **人读产物** | 阶段文件夹 | `[序号] 文件名-{日期}.md` | `[01] 商机档案-2026-08-04.md` |
| **会议记录** | `00-项目资料/会议记录/` | `{日期}-{主题}-{参会人}-逐字稿/纪要.md` | `2026-08-03-方案评审会-张总李工-纪要.md` |
| **客户资料** | `00-项目资料/客户提供/` | 原样存放 | `需求说明书-学工系统.pdf` |
| **模板** | `templates/` 仓库内 | `xxx模板.md` | `project-context模板.md`（不进项目） |

## 使用说明

### 1. 初始化

```bash
# 创建项目根目录
mkdir "学工系统-2026"
cd "学工系统-2026"

# 创建阶段文件夹（初始状态均为 ○ 未开始）
mkdir "00-项目资料" "00-项目资料/客户提供" "00-项目资料/会议记录"
mkdir "○ 01-商机确认" "○ 02-方案报价" "○ 03-签约立项"
mkdir "○ 04-需求分析" "○ 05-设计" "○ 06-架构" "○ 07-开发" "○ 08-测试验收"

# 机器文件：直接放项目根（从 delivery-flow 的 templates 复制并填项目信息）
# - SPEC.md（PRD/UX 阶段产出）
# - project-progress.yaml（从 templates/project-progress模板.yaml 复制并改为全 pending）
# - sprint-status.yaml（飞书 sprint-sync 后续生成）
# - _映射表.json（feishu-sync 后续生成）
```

### 2. 阶段推进

每完成一个阶段并通过关卡后：
1. 将该阶段文件夹的 `▶ ` 改为 `✅ `
2. 将下一个阶段的 `○ ` 改为 `▶ `
3. 更新**项目根** `project-progress.yaml` 中的 `current_stage`

### 3. 文件命名速查

| 场景 | 命名规则 | 示例 |
|------|---------|------|
| 阶段产物 | `[序号] 文件名.扩展名` | `[01] SPEC.md` |
| 有日期版本的文件 | `{类型}-{YYYY-MM-DD}.md` | `报价单-2026-08-04.md` |
| 会议记录 | `{日期}-{主题}-{参会人}.md` | `2026-08-03-方案评审会-张总李工.md` |
| 客户提供资料 | 原样存放，不改文件名 | `需求说明书-学工系统.pdf` |
| 机器文件 | 项目根固定名 | `SPEC.md`、`project-progress.yaml` |

### 4. 注意事项

- **机器文件放项目根**：SPEC.md / project-progress.yaml / sprint-status.yaml / _映射表.json。`core.py` 自动按根 → 阶段目录 → `_meta` 兼容读取。
- **售前原型 vs 正式原型**：售前原型在 `02-方案报价/演示原型/`，正式原型在 `05-设计/演示原型/`，两者分开存放
- **原型标注**：售前原型首页必须标注"售前演示用，交付阶段将基于正式 UX 设计重新生成"
- **`.gitkeep` 文件**：空目录放 `.gitkeep` 以纳入 git 版本控制
- **不创建 `_meta/`**：新项目不要建 `_meta/` 目录——所有机器文件直接放项目根
- **不自动迁移**：如果接手的旧项目用了阶段目录或 `_meta/` 放机器文件，`core.py` 会自动识别，不动用户文件
